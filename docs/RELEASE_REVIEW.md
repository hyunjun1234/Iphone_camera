# 출시 준비 검토

## 버전 0.2.4 촬영 영역 바깥 미리보기

검토일: 2026-10-27

사용자가 알려 준 [아이폰 16 기사 사진](https://www.sisajournal-e.com/news/articleView.html?idxno=405684)의 화면 구성을 참고했습니다. 촬영 영역 바깥을 검게 비우는 대신, 셔터와 상단 버튼 뒤까지 같은 카메라 장면이 이어집니다. 바깥에는 검정 10% 음영을 적용해 영상이 약 90% 밝기로 보이게 했습니다. 얇은 테두리로 저장될 영역을 표시합니다.

CameraX의 미리보기와 정지 사진을 전체 화면과 같은 ViewPort에 연결하고, 선택한 촬영 영역의 상대 좌표로 저장 사진을 자릅니다. 전면 미리보기 반전, 셀피 저장 설정과 촬영 방향을 좌표에 반영합니다. 원본도 같은 영역으로 잘라 보정본과 구도를 맞춥니다. 색감 조절창에서는 같은 구도를 축소해 표시하며, 사진을 가져와 편집할 때에는 원래 사진 비율을 유지합니다. [CameraX 좌표 변환 문서](https://developer.android.com/media/camera/camerax/transform-output)

저장 안내가 셔터를 덮어 다음 촬영을 막는 문제도 발견해 안내 위치를 상단 도구 아래로 옮겼습니다. 비율을 바꿔 연이어 촬영하는 통합 테스트로 확인했습니다.

하나의 카메라에서 받은 영상을 사용하며, 다른 렌즈의 화각을 합성하는 기능은 제공하지 않습니다. 전체 영상 중 선택한 영역을 저장하면서 기존 버전보다 화각과 최종 화소 수가 줄어들 수 있습니다. 갤럭시별 렌즈와 확장 모드에서의 구도 일치는 실기기 확인이 남아 있습니다.

단위 테스트 14개, API 35 ARM64 및 GitHub의 x86_64 에뮬레이터 통합 테스트 각 16개, 360×720dp와 글자 크기 130%에서 사용성 테스트 5개를 통과했습니다. 세 비율의 연속 촬영, 프레임 바깥 제외, 회전과 반전 후 원본 및 보정본의 영역 일치, 기존 사진 편집과 스타일 접기를 포함합니다. `lintDebug`는 오류 0개, 기존 경고 22개입니다. 최적화된 릴리스 APK와 기존 업로드 키로 서명한 AAB를 생성하고, 서명 일치와 `bundletool` 구조 및 ZIP 정렬 검사를 통과했습니다.

릴리스 APK를 실행해 세로 590×787 및 가로 787×590 JPG 저장과 EXIF 방향 정규화를 확인했습니다. 이 수치는 에뮬레이터의 가상 카메라 결과이며 갤럭시의 저장 해상도를 뜻하지 않습니다. 촬영 화면과 세 비율, 스타일 목록 및 조절창을 실제 실행 화면으로 캡처했습니다.

## 버전 0.2.3 촬영 화면 개편

검토일: 2026-10-27

- 촬영 화면의 큰 모먼트 제목과 둥근 카드 테두리, 좌우 여백을 없앴습니다. 촬영 비율을 유지하면서 화면에 들어가는 최대 크기로 미리보기를 표시합니다.
- 사진 위에 반복해서 표시하던 ‘아이폰 ○○ 스타일’ 문구를 제거했습니다. 스타일 목록에는 기종 이름만 표시합니다.
- 스타일 목록은 기본으로 접어 두고 하단의 스타일 버튼으로 열고 닫습니다. 닫기 버튼과 뒤로 가기도 지원하며, 접어도 선택과 조절값은 유지됩니다.
- 스타일 목록은 미리보기 크기를 바꾸지 않고 사진 위에 표시합니다. 원본 비교와 배율 버튼을 가리지 않도록 위치를 정했습니다.
- 촬영 비율과 전후면 카메라를 바꾼 직후 이전 미리보기의 준비 상태를 재사용하지 않도록 했습니다. 새 미리보기가 시작되고 카메라가 열린 뒤 셔터를 활성화합니다.

[Apple의 카메라 기본 화면](https://support.apple.com/ko-kr/guide/iphone/iph263472f78/27/ios/27)을 참고해 사진 중심의 배치와 하단 셔터, 작은 조작 버튼을 적용했습니다. 촬영 프레임 밖의 영상을 보여 주는 기능은 구현하지 않았으며, 사진을 화면에 맞추려고 임의로 늘리거나 자르지 않습니다.

단위 테스트 10개와 Android 통합 테스트 14개를 통과했습니다. 360×720dp 화면과 글자 크기 130%에서는 사용성 테스트 5개를 추가로 통과했습니다. 디버그 빌드, 최적화된 릴리스 APK와 서명된 AAB 생성, `bundletool` 검증을 완료했습니다. `lintDebug` 오류는 0개이며 기존 경고 22개가 남아 있습니다. 갤럭시 실기기 확인은 필요합니다.

화면 캡처 중 에뮬레이터의 OpenGL 렌더링 경로에서 일부 버튼이 간헐적으로 빠지는 현상을 관찰했습니다. 같은 릴리스 APK를 유지한 채 에뮬레이터의 HWUI 렌더러를 Vulkan(`debug.hwui.renderer=skiavk`)으로 바꾸자 촬영 화면, 스타일 목록, 색감 조절 화면의 버튼이 정상으로 표시됐습니다. 문서 이미지는 이 환경의 실행 화면입니다. 앱에서 기기의 렌더러 설정을 바꾸지는 않으며, 갤럭시 실기기 표시 여부는 별도로 확인해야 합니다.

## 버전 0.2.1 사용성 보완

검토일: 2026-10-27

최종 사용성 검토에서 발견한 문제를 수정했습니다. 이번 변경은 화면 조작과 문구에 관한 것으로, 기종별 색감 수치를 변경하지 않았습니다.

| 발견한 문제 | 반영한 변경 |
| --- | --- |
| 같은 스타일을 다시 눌러도 조정값이 초기화됨 | 같은 스타일은 값을 유지하고, 다른 스타일로 이동했다 돌아오면 마지막 강도와 온도, 대비를 복원. 앱 재실행 시에도 보존하며 이전 버전의 활성 스타일 설정도 유지 |
| 촬영 후 원본 비교 버튼의 표시가 화면과 어긋남 | 비교 상태를 화면에서 함께 관리하고 촬영 및 백그라운드 전환 시 해제. 탭으로 전환하거나 길게 눌러 잠깐 비교할 수 있음 |
| 색감 조절창이 사진과 비교 버튼을 가림 | 사진 아래에 조절창을 배치하고 비교 버튼을 사진 밖으로 이동. 가져온 사진은 원래 비율로 표시 |
| 초기화가 다른 탭과 촬영 노출까지 되돌림 | 현재 항목만 초기화하고 버튼에 ‘온도 초기화’처럼 대상을 표시 |
| 원본과 보정본이 함께 저장되는데 안내가 불분명함 | 실제 저장 결과에 맞춰 한 장 또는 두 장의 저장 안내를 구분. 원본 저장 설정에도 두 장을 저장한다고 명시 |
| ‘톤’과 체크 아이콘만으로 동작을 이해하기 어려움 | 조절 항목을 ‘대비’로 변경하고 사진 편집 화면에 ‘사진 저장’ 버튼 표시. 야간 촬영 안내와 설정 유지 설명도 실제 동작에 맞게 수정 |

단위 테스트 10개와 API 35 ARM64 에뮬레이터 통합 테스트 13개를 통과했습니다. 작은 화면(360×720dp)과 글자 크기 130%에서도 조절 화면의 사진과 버튼, 패널이 모두 보이는지 추가로 검사했습니다. 디버그 APK, 최적화된 릴리스 APK와 AAB 빌드가 성공했고 `lintDebug` 오류는 0개입니다. 기존 경고는 남아 있습니다.

미리보기 이미지는 버전 0.2.1을 실행해 갱신했습니다. 갤럭시 실기기 확인과 아래의 배포 준비 항목은 여전히 남아 있습니다.

| 원본 보관과 편집 | 제공 | 원본 바이트 보존, 색감 적용, 투명 이미지 처리, 손상 파일 거부 테스트 |
| 최근 사진과 공유 | 제공 | MediaStore 저장과 URI 읽기 권한 처리. 외부 갤러리 및 공유 앱별 실기기 확인 필요 |

CameraX 확장 기능은 제조사와 렌즈의 지원 여부에 따라 달라집니다. [Android의 Camera Extensions 문서](https://developer.android.com/media/camera/camera-extensions)

## 실행한 검증

환경은 JDK 21, Android SDK 36, API 35 ARM64 에뮬레이터입니다.

```sh
./gradlew assembleDebug testDebugUnitTest lintDebug connectedDebugAndroidTest bundleRelease assembleRelease
```

- 단위 테스트 10개 통과
- Android 통합 테스트 6개 통과
- 디버그 APK, 최적화된 릴리스 APK, AAB 생성 성공
- 린트 오류 0개. 의존성 업데이트 권장, 세로 화면 고정, 일부 API 사용 등 경고는 남음
- 릴리스 APK를 테스트용 키로 서명한 복사본으로 실행 확인. 볼륨 버튼으로 가로 사진을 촬영해 1280×960 JPG와 EXIF 방향 정규화 확인
- APK의 네트워크 및 위치 권한 없음 확인. 카메라 권한과 Android 9 이하의 저장소 권한 사용
- 한국어 촬영 화면, 색감 조절, 설정과 앱 정보 화면 확인. 글자 크기 130%에서 기종명과 촬영 버튼 접근 확인

테스트용 서명은 생성물 복사본에만 적용했습니다. 배포 서명 설정이나 키를 저장소에 넣지 않았습니다. 에뮬레이터 화면은 [미리보기 이미지](screenshots/camera.png)에서 볼 수 있습니다.

## 출시 전에 남은 확인

1. 지원할 갤럭시 기기와 One UI 버전을 정하고 플래시, 초점 고정, 셀피 반전, 각 촬영 비율과 화면 구도를 검증해야 합니다. HDR, 야간, 인물 모드는 렌즈별 지원과 촬영 실패 후 복구를 확인해야 합니다.
2. 실제 기기에서 장시간 촬영, 발열, 메모리 부족, 저장 공간 부족, 권한 철회, 다른 카메라 앱과의 충돌, 프로세스 종료를 확인해야 합니다. Android 8과 9의 저장 경로도 실제 지원 기기에서 검증해야 합니다.
3. 기종별 색감 재현을 홍보하려면 같은 장면을 갤럭시와 아이폰으로 촬영한 데이터와 별도 평가 결과가 필요합니다. 현재는 [직접 설계한 스타일](COLOR_EVIDENCE.md)이라는 설명을 유지해야 합니다.
4. 운영자명과 문의처, 공개된 개인정보처리방침 주소, 배포용 서명을 준비해야 합니다. 현재 앱 안의 데이터 처리 설명은 운영자 정보가 갖춰진 배포용 개인정보처리방침을 대신하지 않습니다. 스토어 설명과 데이터 보안 항목도 실제 동작에 맞춰 작성해야 합니다.

브랜드 이름으로 공식 앱처럼 보이게 하거나 실제로 없는 기능을 광고하지 않도록 스토어 표시도 검토해야 합니다. 관련 기준은 [Google Play 사칭 정책](https://support.google.com/googleplay/android-developer/answer/9888374?hl=en)과 [사용자 데이터 정책](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en)에서 확인할 수 있습니다.
